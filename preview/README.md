# UI preview

A browser mirror of the **Forever Exiled** desktop app. It exists because the real
thing is a Windows-only .NET MAUI binary: you can look at, click through and judge the
interface long before the first `dotnet build`.

> **The data you see is synthetic.** `data/demo-snapshot.json` is generated by
> `tools/generate_demo_snapshot.py`: skill shares, DPS, class splits and character names are
> invented to exercise the UI. The page says so in a permanent banner, badges the header
> `SYNTHETIC SAMPLE`, and calls the league `Allflame (demo)`. None of it is the live ladder.

```bash
python3 preview/serve.py        # → http://localhost:8080
```

Open the URL, press `1`–`4` to jump between screens, `/` to focus the skill search.

## What each screen shows

| Screen | Cards |
| --- | --- |
| `1` Cluster Lab | skill rail · skill hero · size switch · combination list · right rail: top combination, **Crafting**, DPS spread, coverage |
| `2` Meta | league tiles · most popular combinations (tap a row to price it) · right rail: most used notables, **Crafting** |
| `3` Ladder | searchable character table |
| `4` Settings | data source, thresholds, cache |

The Meta tab carries no DPS-leaders or highest-DPS-builds card: the leaders are already the
skill rail on the lab screen, and the crafting card is the more useful occupant. The lab does
not repeat the cluster-size breakdown as a card either — the Large / Medium / Small switch
above the combination list already covers it.

## What is real and what is simulated

| Real | Simulated |
|---|---|
| Layout, palette, type scale, all copy | `SYNC`, `ANALYZE`, `SAMPLE ALL` — a progress overlay runs, then says so |
| Aggregation: combo keys, per-build de-duplication, share-of-sample, weighted DPS, peak DPS, anchoring build, notable usage, class and size mix | Network calls — the page only ever reads `data/demo-snapshot.json` |
| Skill search, DPS/popularity sort, Large/Medium/Small switch, meta size filter, ladder sorting and filtering | League switching |
| **Popularity floor slider** — genuinely re-runs the analysis and re-ranks everything | Cache / folder actions (toasts explain) |
| CSV export (downloads from the sample) | |
| Meta size filter (All / Large / Medium) — a preview extra: the desktop Meta screen shows the combined top 12 | |

The numbers are produced by the same rules as `MetaAnalyzer.cs`, so they match what the
Windows app shows for the bundled snapshot: 18 tracked skills, 234 characters,
576 cluster jewels, 41 distinct combinations, Winter Orb → Medium → *Eye to Eye + Repeater*
at 53.8 % of sampled builds — all of it invented demo data.

### Showing real data

Copy a real crawl over the demo and the banner disappears automatically:

```bash
cp path/to/snapshot.json preview/data/live-snapshot.json
```

The file is the app's own cache format (`snapshot-<league>.json` inside its data folder —
the exact path is shown in the app under *Settings › Local cache*, which also has
**Open folder** / **Copy path** buttons). Anything whose `source` is not `sample` is treated
as live, so the header switches to `LIVE LADDER` and the synthetic notice is hidden.

You do not need the desktop app for this — the headless capture tool writes the file directly:

```bash
dotnet run --project tools/ForeverExiled.Capture -- --preview
```

## Smoke test

`tools/preview_smoke_test.js` loads this page in jsdom and drives every screen —
skill selection, size switch, search, the four tabs, ladder filter/sort, the popularity
floor and the busy overlay — then asserts that each one rendered real numbers:

```bash
npm install jsdom                    # anywhere on NODE_PATH
node tools/preview_smoke_test.js     # 28/28 checks passed
```

## Files

| File | Purpose |
|---|---|
| `index.html` | App shell, four screens, icon sprite |
| `styles.css` | Design tokens copied from `Themes/Colors.xaml` + `Themes/Styles.xaml` |
| `app.js` | Aggregation port of `MetaAnalyzer`/`DpsFormatter` + rendering |
| `data/demo-snapshot.json` | Copy of the synthetic snapshot embedded in `ForeverExiled.Core` |
| `data/live-snapshot.json` | Optional real crawl; overrides the demo when present |
| `assets/` | Logo and cluster jewel art from the MAUI resources |
| `serve.py` | Dependency-free static server (binds `0.0.0.0`) |

This folder is a design aid, not part of the shipped application and not referenced by
`ForeverExiled.sln`. If the C# models change, `app.js` needs the same edit.

## Assets

| Path | What it is |
| --- | --- |
| `assets/logo.png` | Project mark (generated). |
| `assets/notables.json` | 300 cluster-jewel notable descriptions (stats + reminder text) built from Path of Building's tree data; the hover card prints them under each notable. |
| `assets/notable_weights.json` | Spawn weight of all 291 notables per cluster base, plus the generic small-passive mods that compete for the same slot (54 pools, 11,000-14,000 weight each at endgame item levels) from the game's mod data; the hover card prints the pool line and each notable's weight and odds. |
| `assets/tag_colors.json` | One hue per mod tag - the 30 leaf tags the site shows (damage, fire, cold, life, speed...), not the composite `X_damage`/`resource` tags. Colours the tag chips on the item card and in the crafting card; mirrored into the app by `tools/sync_tag_colors.py`. |
| `assets/currency_costs.json` | Chaos-equivalent prices for the crafting card, defaulted to the league craftofexile.com priced its methods in. Placeholders - edit them to match your league. |
| `assets/gems/` | 507 skill gem icons (78px) plus `index.json`, so a skill row can show its real gem art and fall back cleanly when a gem has none. Art from PoE-Gems / Grinding Gear Games. |
| `assets/cluster_{large,medium,small}.png` | Real in-game cluster jewel icons (transparent), so pills and combo cards match the item art. Art from ExileCraft / Grinding Gear Games. |
| `assets/asc/<class>.jpg` | Ascendancy and base-class portraits, shown next to every class name. Art from Path of Building / Grinding Gear Games. |

Regenerate the gem index and the app's copies with `python3 tools/sync_gem_art.py`.
## Hover cards

Hovering a cluster jewel anywhere in the preview builds an item card from the jewel that
represents the combination (`representative` on each combo, kept by the analysis): name in its
rarity colour, base type, passive count, enchant, item level and flags, with each notable
followed by its stat lines and reminder text from `assets/notables.json`. It is positioned against the cursor, flips sides near the window
edge, and disappears on scroll, resize, blur or mouse-leave.
